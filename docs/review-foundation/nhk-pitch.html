Concept proposal / Working prototype

映像レビューを、
修正作業までつなぐ。

Dropbox上の映像に対するコメント、修正指示、字幕修正を同じ時間軸で扱い、 DaVinci Resolveなど次の制作工程へ渡すためのレビュー基盤構想です。

Handover Review Foundation NHK向け検討資料 2026.06.11
01

Why this matters

レビューの情報は、
制作工程の途中で分断されやすい。

映像そのものはDropboxにある一方で、指摘はチャットや表計算、字幕修正は別ツール、 編集反映はNLEへの手入力になりがちです。

1

指摘の所在が散る

「何秒の、どの範囲を、どう直すか」が会話の流れに埋もれます。

2

字幕だけ別工程になる

発話単位の調整、表示遅延、表記確認がレビュー結果と切り離されます。

3

編集側で再入力する

確定した修正内容をNLEへ移す際に、転記と確認が再発します。

目標は「動画にコメントできること」ではなく、レビュー結果を制作データとして次工程へ渡せること。

ひとつの時間軸で、
確認から受け渡しまで。

→
02 / REVIEW

コメント・指示

→
03 / CAPTION

字幕修正

同じ範囲に字幕、話者、行別の表示調整を保持します。

→
04 / HANDOFF

NLE・自動処理

CSV、XML、JSONなど用途別の形式へ変換して渡します。

現行実装

Handoverがすでに持つ土台

Dropbox直接再生、時刻付きコメント、番組・話数の整理、在席表示、Premiere XML / DaVinci CSV出力。

04

Unified data model

違う作業を、同じ「Marker」として扱う。

コメント、修正指示、字幕を別々の機能として閉じず、時間位置を持つ共通データにします。

POINT

一点コメント

特定フレームへの確認、感想、質問。終了時刻を持ちません。

kind: comment
start_s: 72.4
end_s: null
RANGE

範囲修正指示

カット、差し替え、音量調整など、開始・終了を持つ指示です。

kind: instruction
start_s: 72.4
end_s: 76.8
CAPTION

字幕

本文、話者、行分割、行別遅延、承認状態を同じ範囲に保持します。

kind: caption
status: approved
delay_ms: 120
共通モデルにすることで、レビュー画面、字幕編集、書き出し、自動処理を同じ履歴から組み立てられます。
05

Human in the loop

判断は人に残し、
転記と反復を機械に渡す。

EDITORIAL JUDGMENT

人が担うこと

  • 事実関係、固有名詞、表現の妥当性
  • 映像と音の意図を踏まえた採否判断
  • 公開可能性と最終承認
  • 例外や曖昧さへの対応
共通
Marker
AUTOMATION

機械に渡せること

  • 時刻、範囲、状態の保持
  • 書式変換とNLEへの受け渡し
  • 修正指示の一覧化と進捗集計
  • 字幕生成など外部処理との接続
自動字幕生成やレンダリングはHandover本体へ抱え込まず、用途別の処理基盤をアダプターで接続する設計を想定しています。
06

Current reality

「できていること」と
「これから」を分けて提示する。

区分 確認できる内容 位置づけ
現行実装 Dropbox直接再生、時刻付きコメント、フォルダ・話数管理、在席表示、CSV / XML出力 既存コードで動作する土台
動作試作 範囲指示、字幕、共通インスペクター、行別遅延、Marker JSON、検証表示 操作とデータ設計を確認する試作
次段階 安全な共有リンク、権限、変更競合、版管理、DaVinci往復、監査ログ 業務検証前に必要な実装
現時点のHandoverは小規模チーム向けの試作です。認証・権限・共有URLの扱いは業務利用の要件を満たしておらず、 本番データを投入する段階ではありません。「Frame.ioの完成代替」ではなく、Dropboxを起点にしたレビュー基盤の検証対象です。
07

Target architecture

レビューを中心に、
既存の制作環境と接続する。

MEDIA

Dropbox

動画の保管と版の起点。素材を別サービスへ複製しない運用を基本とします。

→
REVIEW CORE

Handover

Project / Asset version / Marker / Review sessionを保持し、人の確認と制作データを結びます。

↔
ADAPTERS

制作ツール

DaVinci Resolve、字幕処理、レンダリング、公開処理へ用途別に接続します。

安全な共有

期限付きトークンとviewer / reviewer / editor / ownerの役割を導入。

変更の整合性

版番号と楽観ロックで、同時編集時の上書きを検知。

DaVinci連携

まず書き出しを安定化し、その後に修正結果の往復を検証。

08

Implementation path

業務利用の前に、
信頼できる順番で積み上げる。

0

現行環境の確定

実際のDB構造、利用状況、データ境界を確認し、監査の前提を固定。

1

共有と権限の再設計

安全なレビューリンク、期限、役割、監査ログを実装。

2

Markerモデルへ移行

既存コメントを保持しながら、範囲指示と字幕を共通化。

3

レビュー画面を実装

タイムライン、インスペクター、状態管理、競合検知を整備。

4

字幕・外部処理を接続

字幕編集、生成処理、レンダリングをアダプターとして接続。

5

DaVinciとの往復検証

書き出しから開始し、編集結果を戻す運用まで段階的に確認。

09

Small pilot proposal

まず一つの制作単位で、
本当に減る手間を測る。

大規模導入を前提にせず、非機密の検証素材と少人数の制作チームで、 レビューから修正反映までの流れを観察します。

検証する流れ

  • Dropbox上の1本の映像を登録
  • 複数担当者がコメント・範囲指示を入力
  • 字幕修正を同じ時間軸で承認
  • DaVinci向けデータを書き出して反映
  • 結果と未解決事項をレビュー

見る指標

指摘回収に要した時間
転記・再入力の回数
重複・見落としの件数
修正完了までの往復数

定量値に加え、編集者・制作者が「判断しやすかったか」を短い聞き取りで確認します。
